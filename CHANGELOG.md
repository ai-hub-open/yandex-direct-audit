# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/). Описание для пользователей — `docs/releases/`.

## 1.2.0 — 2026-10-09

**Открытый репозиторий, установка плагином Claude Code и сообщение о новой версии.** Описание для
пользователей — [`docs/releases/v1.2.0.md`](docs/releases/v1.2.0.md). Режимы и шаги не менялись.

- **Лицензия Apache-2.0** (`LICENSE`), как у `yandex-direct-manager`, `marketing-strategist` и
  `vk-ads-manager`: репозиторий открывается.
- **Плагин:** `.claude-plugin/plugin.json`, скилл ставится из маркетплейса `ai-hub-open/claude-plugins`.
  Файлы скилла остаются на прежних местах — бандл для Claude Desktop собирается как раньше.
- **`VERSION`** + **проверка версии** один раз за разговор, до mode-gate: скилл сверяет `VERSION`
  с `main` на GitHub и, если вышла новая, говорит, как обновиться. Без сети молча идёт дальше.
  Файлы сам не заменяет.
- **Рабочие папки — вне папки скилла.** В «Как использовать scripts» явно: `direct-audits/` и
  `lead/` живут в текущей папке пользователя, скрипты из папки скилла получают абсолютные пути.
  Плагин при обновлении заменяет свою папку целиком — данные клиента там бы пропали.
- **`make_bundle.py`:** `.claude-plugin/` не попадает в бандл; `VERSION` и `LICENSE` попадают.
  Заодно исключён `.pytest_cache/` — локальный кеш тестов раньше уезжал в бандл.
- **CI:** `.github/workflows/version-check.yml` сверяет версию в `plugin.json`, `VERSION`, верхней
  записи `CHANGELOG.md` и в теге релиза.
- **README:** установка плагином в Claude Code (коннектор через `claude mcp add`), готовый
  `.zip` в релизах, раздел «Лицензия».

## 1.1.0 — 2026-10-08

**История каналов как явный артефакт и журнал правок в Windows.** Описание для пользователей —
[`docs/releases/v1.1.0.md`](docs/releases/v1.1.0.md).

- **История каналов** — новый `references/channel-history.md`: как называется артефакт
  (`channel_history.md` + `.json`; у менеджера — `_channel_history.md`), где его искать (папки
  стратега `marketing-campaigns/<slug>/`, менеджера `direct-campaigns/<slug>/`, ведения
  `lead/<slug>/`, вложения), контракт полей (общий с `marketing-strategist` и
  `yandex-direct-manager`), чем отличается от `baseline.json`, как его использует `strategy.md`,
  что делать без истории и как собрать её из кабинета (аудит — производитель файла).
- **Шаг 0:** поиск готовой истории (обычно её уже собрал стратег); находки по типам кампаний,
  которые по истории не давали лидов, получают строку контекста. Без истории — пометка и
  предложение выгрузить её в конце аудита.
- **Быстрый выход «выгрузи историю каналов»:** Шаг 0 → сборка истории по периоду и определению
  лида, которые выбирает человек, → `channel_history.md` + `.json`, без полного аудита.
- **Ведение:** четвёртый источник стратегии — папка `marketing-strategist`; блок `history` в
  `strategy.md` (`works_types`, `weak_types`, `history_cpa`); наращивание `weak_types` —
  рекомендация, не действие; `target_cpa` сверяется с фактическим CPA из истории.
- **Метрика:** рецепт M7 — источники трафика (рекламные системы и UTM) для не-Директ каналов.
- **`scripts/channel_history.py`:** `build` сворачивает дневной отчёт Директа по типам кампаний,
  добавляет ручные строки (черновики, другие каналы), считает CPA и выводы по порогам
  (`works / expensive / no_leads / no_data / never_ran` с `verdict_reason`) и пишет
  `channel_history.json` + `.md`; `validate` проверяет готовый файл от стратега или менеджера.
  Период и определение лида не подставляет. Фикстура и eval 13 — все пять выводов.

- `scripts/changes_log.py` переключает stdout/stderr на UTF-8, как соседние скрипты. Раньше в
  Windows-консоли падали `--help` (кириллица в описаниях) и вывод ✅/⚠️. Хуже всего — `record`:
  строка уже попадала в журнал, а печать подтверждения роняла процесс с кодом 1, и агент мог
  записать ту же правку повторно. Проверены `--help`, `record`, `list`, `rollback-plan`,
  вывод в файл; журнал по-прежнему в UTF-8.
- Справка скрипта: журнал ведётся и в точечном режиме (`direct-audits/<slug>`), и в ведении
  (`lead/<slug>`); подсказка, как передавать JSON в Windows PowerShell 5.1 (экранировать кавычки).

## 1.0.1 — 2026-10-06

**Исправления по большому тесту в Claude Desktop.** Описание для пользователей —
[`docs/releases/v1.0.1.md`](docs/releases/v1.0.1.md).

- **Деньги:** отчёты — в рублях, настройки кампаний и ставки (`campaigns_get`, `keywords_get`,
  `keywordbids_get`) — в микро, делить на 1 000 000; при записи — наоборот. Убраны
  противоречивые «всегда в рублях» и «ничего не делим».
- **Оплата за конверсии:** блок в `references/audit-thresholds.md` — как распознать
  (`PAY_FOR_CONVERSION*`), какие пороги не применять (клики бесплатны, экономии нет), что
  смотреть вместо (цель оплаты, мусорные конверсии, цена конверсии против KPI). Ссылки из Шага 1,
  правил минусации и субагентов.
- **Точечный режим:** «проверь кампанию и поправь» — выбранные кампании → диагноз → превью правок
  → запись после «ОК», журнал правок в папке сессии, дефолтные пределы ±20 %, без `strategy.md`
  и Цикла 0.
- **Шаг 0:** кабинет подтверждается всегда (даже если он один), кампании — явным выбором; без
  ответа — стоп. «Весь аккаунт» больше не дефолт.
- **Evals:** поправлены ожидания про микро, добавлены кейсы 10–12.
