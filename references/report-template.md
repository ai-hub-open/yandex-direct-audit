# Шаблон финального отчёта аудита

Шаг 7 собирает все находки в `findings.json` (machine-readable) и `АУДИТ_<slug>.md` (для маркетолога).

## Схема `findings.json`

```json
{
  "meta": {
    "slug": "<проект>",
    "client_login": "<логин или null>",
    "period": "2025-05-01..2025-05-31",
    "compared_to": "2025-04-01..2025-04-30 | null",
    "attribution": {
      "default_direct": "LSCCD",
      "default_metrika": "cross_device_last_significant",
      "note": "Модель берётся отдельно из настроек каждой кампании; это запасной дефолт для кампаний без явной модели (последний значимый переход, кросс-девайс). Конкретная модель кампании указана в evidence находки (Direct-код + имя Метрики)."
    },
    "kpi": { "cpa": 1500, "drr": 0.15 },
    "limitations": [
      "Метрика не привязана к кампаниям X, Y — конверсии/отказы не оценены",
      "api_call не достаёт reports — площадки собраны частично"
    ]
  },
  "findings": [
    {
      "id": "F1",
      "area": "placements | search_queries | bid_modifiers | creatives | structure | profitability",
      "severity": "high | medium | low",
      "title": "Площадка X сливает бюджет без конверсий",
      "evidence": "Расход 12 400 ₽ за 30 дней, 310 кликов, 0 конверсий, CTR 3.1% (сеть)",
      "threshold": "Сеть: ноль конверсий при расходе выше среднего + CTR ≥2% (подозрение на фрод)",
      "recommendation": "Добавить площадку в ExcludedSites кампании «РСЯ-1»",
      "expected_effect": "Высвобождение ~12 400 ₽/мес на конвертящие площадки",
      "confidence": "high | medium (мало данных)",
      "volume_note": "достаточно данных | <10 конверсий, гипотеза"
    }
  ]
}
```

## Структура `АУДИТ_<slug>.md`

```markdown
# Аудит Яндекс.Директа — <проект>

**Период:** <даты> (сравнение с <даты> | без сравнения)
**Аккаунт:** <логин>
**Модель атрибуции:** определяется отдельно для каждой кампании из её настроек (если не задана — `LSCCD` ↔ `cross_device_last_significant`, последний значимый переход с кросс-девайсом); та же модель применена в Метрике. Указана рядом с конверсионными числами; модель каждой кампании проставлена в её находках.
**KPI:** CPA ≤ <X> ₽ / ДРР ≤ <Y>%

## Резюме (топ-5)
Короткий список самых дорогих находок и суммарный потенциал экономии/роста.

## 1. Что нашли (по приоритету)

### 🔴 High — деньги текут сейчас
Таблица: находка | доказательство | порог | рекомендация | эффект

### 🟡 Medium — упускаемый потенциал
...

### 🟢 Low — гигиена
...

## 2. Что рекомендуем сделать (чек-лист для маркетолога)
Сгруппированный по областям список действий. Каждое — с числом-обоснованием.
Помечено, что внедряется руками (скилл ничего не менял).

## 3. Чего не смогли проверить (ограничения)
Честный список: нет связки с Метрикой где-то, api_call не достаёт reports,
сегменты с малым объёмом, и т.п.

## 4. Приложения
Ссылки на детальные артефакты (02_…json, 03_…json, и т.д.)
```

## Принципы оформления

- **Три раздела всегда разделены:** что нашли (диагноз) / что рекомендуем (действия) / чего не проверили (ограничения). Не смешивай диагноз с рекомендацией в одну кашу.
- **Деньги — в рублях**, период указан, объём данных указан.
- **Каждая рекомендация привязана к находке** и порогу. Нет «вообще стоит улучшить тексты» — есть «в группе X одно объявление, добавить 2-й вариант для теста».
- **Приоритизация по деньгам:** сортируй high по абсолютному расходу, который высвобождается/растёт. Маркетологу важно, что вернёт больше денег быстрее.
- **Скилл ничего не внедрял** — это явно сказано в разделе рекомендаций. Решение по каждому пункту за человеком (особенно списание запросов в минус и отключение площадок в сезонных/НЧ-нишах).
- **Сводка в чат — 5-10 строк**, полотно отчёта — в файл, показать ссылкой.
