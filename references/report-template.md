# Шаблон финального отчёта аудита

Шаг 7 собирает все находки в `findings.json` (machine-readable), а из него скрипт
`scripts/render_report.py` собирает **готовый HTML** `АУДИТ_<slug>.html` в стиле «дашборд» —
один самодостаточный файл с вёрсткой под печать A4. Это и есть то, что получает маркетолог:
он открывает файл в браузере, а если нужна печатная версия — Ctrl+P → Сохранить как PDF.

## Принципы (обязательны — это требования к отчёту)

- **Финал — собранный документ.** Не Markdown-простыня, а дашборд. Открывается у маркетолога как готовый отчёт.
- **Группировка по кампаниям.** Основная рабочая часть — разделы по кампаниям: в какой кампании что сделать. Приоритет по деньгам не теряется — он в верхнем блоке «Главное».
- **Готово к ручному применению.** Каждое действие самодостаточно: что сделать, готовый список для вставки (минус-слова/площадки — целиком в теле), где это в Директе, почему, **как перепроверить самому**, уверенность. Маркетолог берёт и применяет вручную; если пункт кажется спорным — строка «проверить самому» даёт ему проверить за минуту.
- **Человеческий язык, без жаргона.** Никаких `CUSTOM_REPORT`, кодов атрибуции `LSCCD`, имён срезов API — это внутренняя кухня, в отчёт не выносится. Действия формулируются как простые инструкции.
- **Без математических символов.** Пиши словами: «не больше 1 500 ₽», «не меньше», а не `≤`/`≥`.
- **Деньги в рублях.** Период и объём данных указаны.
- **Скилл ничего не менял** — это явно сказано в подвале и в формулировках действий («внедряет маркетолог»).

## Как собрать отчёт

```
python -m scripts.render_report --input direct-audits/<slug>/findings.json
# по умолчанию рядом появится АУДИТ_<slug>.html
# --output <путь.html> — своё имя
```

Ни pip-пакетов, ни браузера, ни сети скрипт не требует — поэтому работает и в песочнице
Claude Desktop. На экране файл читается как страница, при печати вёрстка переключается на
A4 с разрывами по карточкам. Список полей схемы — ниже.

## Схема `findings.json`

```json
{
  "meta": {
    "slug": "<проект>",
    "client_login": "<логин или null>",
    "period": "2025-05-01..2025-05-31",
    "compared_to": "2025-04-01..2025-04-30 | null",
    "kpi": { "cpa": 1500, "drr": 0.15 },
    "summary": {
      "currency": "RUB",
      "total_cost": 320000,
      "avg_cpa": 1800,
      "recoverable": 25000,
      "growth_potential": 18000
    },
    "campaigns": [
      { "name": "Поиск-1", "type": "Поиск", "cost": 180000,
        "cpa": 1900, "drr": 0.18, "kpi_status": "выше KPI" }
    ],
    "limitations": [
      "К кампании X не привязан счётчик — конверсии и отказы не оценены",
      "Отчёт по площадкам не собрался за две попытки — площадки собраны частично"
    ]
  },
  "findings": [
    {
      "id": "F1",
      "campaign": "РСЯ-1",
      "area": "Площадки РСЯ",
      "severity": "high | medium | low",
      "money_impact": 12400,
      "title": "Три площадки жгут бюджет без заявок",
      "recommendation": "Отключить площадки — добавить в исключения кампании «РСЯ-1».",
      "where": "Кампания «РСЯ-1» → Параметры → Запрещённые площадки.",
      "ready_to_use": ["games.example.com", "play-arena.example.net"],
      "evidence": "12 400 ₽ и 620 кликов за май, 0 заявок. Отказы 80%+, глубина 1,1 страницы.",
      "threshold": "В сети: расход выше 2× цены заявки и ноль конверсий при 100+ кликах.",
      "how_to_verify": "Мастер отчётов → срез «Площадка», отсортируй по расходу.",
      "expected_effect": "Высвобождается ~12 400 ₽/мес.",
      "confidence": "высокая | средняя (мало данных)",
      "volume_note": "данных достаточно | <10 конверсий, гипотеза | не требует объёма"
    }
  ]
}
```

Заполненный образец на 5 находок и 3 кампании — `assets/findings_schema_example.json`
(бери его за шаблон). Назначение полей:

**Блок `meta`:**
- `summary` — питает 4 плашки дашборда: `total_cost` (Расход всего), `avg_cpa` (Средняя цена заявки), `recoverable` (Потенциал экономии — сумма денег, уходящих впустую; обычно ≈ сумма `money_impact` срочных находок слива), `growth_potential` (Потенциал роста — оценка, сколько можно добрать, усилив работающее).
- `campaigns` — питает шкалу «Расход по кампаниям» и статусы по KPI справа от баров. `kpi_status` — короткая фраза («выше KPI» → красный, «в норме» → зелёный); `cpa` и `drr` показываются рядом с расходом.
- `limitations` — раздел «Чего не смогли проверить».

**Каждая находка:**
- `campaign` — к какой кампании относится (по нему идёт группировка в Блоке 2; имя должно совпадать с `meta.campaigns[].name`).
- `area` — человеческое имя области («Площадки РСЯ», «Поисковые запросы», «Корректировки ставок», «Объявления», «Структура», «Прибыльность»). Без техжаргона.
- `severity` — `high` (Срочно, красный) / `medium` (Важно, жёлтый) / `low` (Можно позже, зелёный).
- `money_impact` — рубли/мес для ранжирования топа «Главное»; `null`, если находка не денежная (тогда в топ не попадает).
- `recommendation` — что сделать, простой инструкцией.
- `where` — где это в интерфейсе Директа.
- `ready_to_use` — готовый список для вставки (минус-слова, домены площадок). `null`, если списка нет. Печатается целиком в рамке.
- `evidence` / `threshold` — доказательство (числа+период+объём) и порог, по которому сработало.
- `how_to_verify` — как маркетологу перепроверить самому.
- `expected_effect`, `confidence`, `volume_note` — эффект, уверенность, заметка про объём данных.

## Структура отчёта (что собирает рендер)

**Шапка:** заголовок, крупная строка «Период анализа: 1–31 мая 2025 (сравнение с …)», аккаунт, цель (KPI) словами.

**Блок 1 — дашборд + «Главное».**
- 4 плашки-показателя с подписями (из `meta.summary`).
- шкала «Расход по кампаниям» + KPI каждой кампании справа (цена заявки, ДРР, статус, цвет).
- «Главное — с чего начать»: топ-5 находок по `money_impact` с суммами.

**Блок 2 — «Что сделать в каждой кампании»** (основная рабочая часть).
Кампании по убыванию расхода; внутри — карточки-действия по убыванию важности (high→medium→low).
Каждая карточка: цветная левая полоса по severity, метка важности + область + заголовок,
строка «→ что сделать», готовый список в рамке (если есть), затем строки:
**Где в Директе / Почему / Проверить самому / Эффект / уверенность·объём**.

**Блок 3 — «Чего не смогли проверить»:** честный список ограничений из `meta.limitations`.

**Подвал:** отчёт в режиме «только чтение», скилл ничего не менял, решение за маркетологом.

## Приоритизация

Топ «Главное» — по абсолютным деньгам (`money_impact`). Внутри кампаний — по severity.
Severity расставляется по влиянию на деньги (порядок — `optimization-playbook.md`,
раздел «Приоритизация исправлений»): фундамент и быстрый возврат денег → high; упускаемый
потенциал (корректировки, креативы) → medium; гигиена → low.

## Что в чат, что в файл

- Полный отчёт — **HTML-файл**, показать ссылкой на файл.
- В чат — сводка топ-5 находок, 5–10 строк, не больше.
