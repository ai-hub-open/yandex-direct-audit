# Ведение: безопасная запись в аккаунт

Этот reference работает **только в режиме ведения**. В режиме аудита запись запрещена всегда — см. mode-gate в `SKILL.md`. Здесь — как применять правки в чужом аккаунте так, чтобы «пишет всё одобренное» осталось безопасным. Скилл открытый, поедет в аккаунты, которых мы не видели, поэтому четыре предохранителя обязательны на каждой правке.

Правило номер один остаётся из аудита: **любая правка проходит гейт**. Ничего не пишется в аккаунт без явного «ОК» от человека на конкретный набор изменений. Автоматизируется исполнение одобренного, а не решение.

---

## Предохранитель 1 — journal-before-write (откат)

Перед **каждой** записью:
1. Дёрни соответствующий `*_get` и сохрани текущее значение объекта (ставка, статус, список минусов, бюджет, корректировка).
2. Запиши в `changes_log.jsonl` строку с `before` (что было) — через `scripts/changes_log.py`.
3. Только потом вызывай write-тул и допиши `after` (что стало) + id объекта.

Так любую неудачную правку можно откатить: `before` хранит прежнее значение. Пиши строку лога **сразу после** успешного ответа тула, а не пачкой в конце — при обрыве середины цикла лог покажет, что уже применено, и повторный прогон не создаст дубль.

## Предохранитель 2 — dry-run → диф → запись

Где MCP Директа поддерживает `dry_run` — сначала прогони правку в режиме предпросмотра, покажи человеку тело запроса и предполагаемый эффект, дождись «ОК», потом заливай боевым вызовом. Ответ проверяй целиком: `success: true` может соседствовать с отклонёнными объектами — «вернулось без ошибки» ≠ «всё применилось».

## Предохранитель 3 — guardrails из strategy.md

Перед тем как положить правку в `proposed.json`, сверь её с блоком `guardrails` (`references/lead-strategy.md`):

- ставка/корректировка меняется больше чем на `max_bid_change_pct` за цикл → **обрезать до предела** или вынести рекомендацией, не применять целиком;
- отключается больше `max_placements_off_per_cycle` площадок → взять top-N по сливу, остальное под наблюдение;
- бюджет меняется больше чем на `max_budget_change_pct` (дефолт 20% — порог сброса обучения автостратегии) → обрезать;
- объём данных ниже `min_clicks_for_action` → правки нет, это «мало данных, накопить»;
- объект в `protected` (бренд-РК и пр.) → только рекомендация, автоправки нет.

Всё, что за пределом guardrails, идёт человеку **рекомендацией**, а не действием — с пометкой, какой предел сработал.

## Предохранитель 4 — обратимые vs необратимые

Даже при «пишем всё одобренное» делим правки по цене ошибки:

| Класс | Примеры | Как применяем |
|---|---|---|
| **Обратимые** | добавить минус-слово, отключить площадку, задать/поменять корректировку ставки, изменить недельный бюджет, приостановить/возобновить объявление или ключ | применяем после общего гейта; `before` в лог для отката |
| **Необратимые / дорогие** | удалить кампанию/группу/объявление/ключ, крупная смена стратегии торгов, снятие паузы с кампании (запуск расхода) | **отдельный явный конфирм** на каждую: «это необратимо / это запускает расход — точно?» |

Жёсткое правило, наследуемое из yandex-direct-manager: **скилл сам не активирует остановленную или черновую кампанию.** Старт реального расхода бюджета — всегда отдельная человеческая кнопка, даже внутри «пишем всё одобренное». Активация = деньги + последний человеческий чек (посадочные живы, Метрика пишет, бюджет налит, ОРД-маркировка на месте).

## Карта write-тулов Директа

Ищи по **суффиксу** имени — префикс коннектора задаёт пользователь (`YAD-Original`, `YadLisa`, `yad_gossa`…), не хардкодь его. В режиме ведения разрешены (после гейта), сгруппированы по типовым правкам цикла:

| Правка цикла | Тул (суффикс) | Класс | Перед вызовом (before-снимок) |
|---|---|---|---|
| Минус-слова кампании/группы | `campaigns_update` / `adgroups_update` | обратимая | `campaigns_get` / `adgroups_get` — текущий `NegativeKeywords` |
| Запрещённые площадки РСЯ | `campaigns_update` (ExcludedSites) | обратимая | `campaigns_get` — текущий `ExcludedSites` |
| Корректировки ставок (устройство/гео/пол-возраст/время) | `bidmodifiers_set` / `bidmodifiers_delete` (+ `_demographics`/`_devices`/`_regional`/`_retargeting`) | обратимая | `bidmodifiers_get` — текущие корректировки |
| Ставки по ключам | `keywordbids_set` | обратимая | `keywordbids_get` — текущая ставка |
| Пауза/возобновление ключа | `keywords_suspend` / `keywords_resume` | обратимая | `keywords_get` — текущий статус |
| Пауза/возобновление объявления | `ads_suspend` / `ads_resume` | обратимая | `ads_get` — текущий статус |
| Отправить на модерацию | `ads_moderate` | обратимая | — |
| Бюджет / стратегия кампании | `campaigns_update` | смена стратегии — **необратимая/дорогая** | `campaigns_get` с `include_strategy: true` |
| Пауза/снятие паузы кампании | `campaigns_suspend` / `campaigns_resume` | `resume` — **необратимая** (запуск расхода, отдельный конфирм) | `campaigns_get` — статус |
| Добавить ключи/минусы/расширения | `keywords_add` / `sitelinks_add` / `adextensions_add` | обратимая (добавление) | — (в лог — что добавили, для отката удалением) |
| Удаление любого объекта | `*_delete` | **необратимая** (отдельный конфирм) | полный `*_get` объекта в лог |

Не в этой таблице — не пишем. Если по логике нужна правка без тула (автотаргетинг в ЕПК, пакетная стратегия, временной таргетинг, загрузка картинок на хостовом MCP — см. ограничения в manager-скилле) — она уходит **рекомендацией на ручную работу** в `cycle_report.md`, а не выдумывается через смежный тул.

## Порядок применения в фазе «Применение»

После гейта, по одобренному списку:
1. Отсортируй правки: сначала обратимые дешёвые (минусы, площадки, корректировки), в конце — необратимые с отдельным конфирмом.
2. Для каждой: `*_get` → строка `before` в лог (`scripts/changes_log.py record`) → `dry_run` где есть → боевой вызов → дописать `after` + id.
3. Проверяй ответ целиком (отклонённые объекты при `success: true`).
4. Не применилось → зафиксируй в `applied.json` со статусом `failed` и причиной, не молчи и не выдумывай успех.
5. Собери `applied.json` + обнови `cycle_report.md`: что применено, что ушло рекомендацией (guardrails/необратимое/нет тула), что не удалось.

Откат прошлой правки (если следующий цикл показал вред): `scripts/changes_log.py rollback-plan --cycle <дата>` вернёт `before`-значения одобренных к откату строк — примени их как обычную обратимую правку через тот же гейт.
