# Атрибуция и конверсии в отчётах Директа

Всё конверсионное в аудите зависит от двух вещей: какие **цели** считаем (`goals`) и по какой **модели атрибуции** (`attribution_models`). Этот reference — единственный источник правды по обеим.

## Модели атрибуции — коды Директа

| Модель | Код (`attribution_models`) | Через коннектор |
|---|---|---|
| Первый переход | `FC` | ✅ |
| Первый переход, кросс-девайс | `FCCD` | ✅ |
| Последний переход | `LC` | ✅ |
| Последний переход, кросс-девайс | `LCCD` | ✅ |
| Последний значимый переход | `LSC` | ✅ |
| Последний значимый, кросс-девайс | `LSCCD` | ✅ |
| Автоматическая | `AUTO` | ✅ |
| Последний переход из Директа | `LYDC` | ❌ нет в схеме тула |
| Последний из Директа, кросс-девайс | `LYDCCD` | ❌ нет в схеме тула |

⚠️ `LYDC`/`LYDCCD` через коннектор недоступны. Там, где нужна «модель верха воронки» для сравнения — бери **`FC`** (первый переход). Вывод получается тот же.

## Правило выбора модели (обязательное)

1. **Модель определяется ОТДЕЛЬНО для каждой кампании** — бери её из настроек самой кампании (Шаг 1, `campaigns_get` с `include_strategy: true`). Единой модели «на весь аккаунт» нет.
2. **Кампания не отдала модель** → `LSCCD` (последний значимый переход, кросс-девайс). Это дефолт скилла, поле `attribution_default` в `_state.json`.
3. **Фиксируй модель по каждой кампании** в `01_account_map.json`. В одном отчёте `attribution_models` применяется ко всем строкам сразу — значит, кампании с разными моделями либо группируй по модели, либо запрашивай отдельными отчётами.
4. **Подписывай модель рядом с каждым конверсионным числом.** Числа из разных моделей — не одно и то же, сравнивать их между собой нельзя.

## Кросс-чек воронки в одном отчёте

Direct принимает **несколько моделей за раз**: `attribution_models: ["LSCCD", "FC"]` вернёт колонки `Conversions_<goal>_LSCCD` и `Conversions_<goal>_FC` рядом, по тем же строкам.

Это и есть проверка «кампания убыточна по последнему клику, но она — верх воронки». Если по `FC` конверсий заметно больше, чем по `LSCCD`, кампания приводит людей, которые доходят до заявки позже и через другой канал — **резать её нельзя**, это будет выстрел по всей воронке. Никаких джойнов между системами для этого не нужно.

Ограничение: до 10 целей на запрос. Колонки именуются `Conversions_<goal>_<model>` — перед прогоном анализаторов сверни их в один `Conversions` (сумма по целям в рамках ОДНОЙ модели).

## Когда конверсионные поля приходят пустыми

`Conversions`, `ConversionRate`, `CostPerConversion`, `Revenue`, `BounceRate`, `AvgPageviews`, `Bounces`, `Sessions` наполняются **только если к кампании привязан счётчик Метрики и настроены цели**. Это условие рекламного аккаунта, а не среды.

Пусто везде → это **находка №1 уровня high**, а не сбой инструмента: без целей оптимизация по ставкам и минусация по конверсиям слепые. Аудит продолжается по расходу, кликам, CTR и структуре, все конверсионные выводы помечаются «нет данных».

Проверяется по `CounterIds` в `campaigns_get` (пусто → счётчика нет) плюс по пустым конверсионным колонкам первого же отчёта.

## Чего в Директе нет

- **Время на сайте** (средняя длительность визита) — поля нет ни в одном отчёте. Глубину меряем через `AvgPageviews`, длительность в выводах не используем.
- **Список целей счётчика.** Директ не умеет перечислить цели Метрики — видит только `GoalId` внутри конверсионной стратегии кампании. Поэтому `goal_ids` спрашиваем у маркетолога на Шаге 0.
- **Ассоциированные конверсии** отдельным полем. Их роль играет сравнение моделей атрибуции (см. выше).

Полная поведенческая аналитика вернётся вместе с Метрика-MCP — см. `parked/README.md`.
