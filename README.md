# yandex-direct-audit

> Аудит и ведение работающих кампаний Яндекс.Директа. Два режима в одном скилле.

Скилл работает над работающим аккаунтом Директа в **трёх режимах** через **коннектор Яндекс.Директа** (расход, структура, конверсии, поведение) и опционально **коннектор Яндекс.Метрики** (цели, время на сайте, посадочные, потеря кликов). Собран под **Claude Desktop**.

- **Режим аудита** (по умолчанию) — разовая **read-only диагностика**: от инвентаризации до приоритизированного HTML-отчёта «срезать слив / масштабировать / починить». Ничего не пишет в аккаунт.
- **Точечный режим** — «проверь кампанию и поправь»: выбранные кампании → диагноз тем же движком → превью правок → запись одобренного после явного «ОК», с журналом для отката. Без папки проекта и файла стратегии; пределы правок — дефолтные.
- **Режим ведения** — повторяющийся **недельный цикл управления**: сверка с целью проекта (`strategy.md`) → диагноз тем же движком → проверка эффекта прошлых правок → применение одобренных изменений в аккаунт под гейтом, с журналом (`changes_log.jsonl`) и откатом. Состояние живёт в папке на диске и переживает новые сессии.

Режим выбирается **mode-gate** в начале `SKILL.md`. Создание новой кампании с нуля — не задача этого скилла.

## С чего начать (навигация по пакету)

## Что делает — 7 шагов

0. Подключение коннектора, предполётные проверки, скоуп аудита (период, KPI, цели)
1. Инвентаризация и структурный аудит
2. Статистика по кампаниям (+ кросс-чек воронки: две модели атрибуции в одном отчёте)
3. ⭐ Майнинг поисковых запросов: минусация + действия по фразам (ядро бывшего phrase-minus) — **форк** `search-queries`
4. ⭐ Чистка площадок РСЯ (ядро бывшего rsya-minus) — **форк** `rsya-placements`
5. ⭐ Корректировки ставок (точки роста) — **форк** `bid-segments`
6. Объявления и релевантность
7. Сборка финального HTML-отчёта (дашборд, печатается в PDF из браузера)

## Режим ведения — недельный цикл

Тот же диагностический движок (Шаги 1–6), обёрнутый в повторяющийся недельный цикл с целью и записью правок. Полная логика — `SKILL.md` → «Режим ведения», методология — `references/lead-strategy.md` (дом состояния, схема `strategy.md`, 3 источника bootstrap, возобновление) и `references/lead-write-safety.md` (гейт, journal-before-write, dry-run, guardrails, обратимые/необратимые, карта write-тулов).

- **Цикл 0 (разово):** подключить папку проекта → собрать `strategy.md` (готовый файл стратегии / автовывод из папок стратега и скилла создания — вместе с историей каналов / интервью + baseline) → зафиксировать `baseline.json`.
- **Цикл N (еженедельно):** ревизия прошлых правок (сердце ведения) → диагноз относительно цели → план правок с проверкой guardrails → гейт → применение одобренного с записью в `changes_log` → закрытие цикла.

Состояние живёт на диске пользователя (`<project_dir>/lead/<slug>/`), а не в эфемерной сессии — поэтому ведение переживает новые сессии и еженедельный такт. Скрипт `scripts/changes_log.py` ведёт журнал правок с before/after и собирает план отката.

## Архитектура: оркестратор + субагенты

Оркестратор держит общую картину в основном контексте (скоуп, `_state.json`, гейты, сборка отчёта). Три тяжёлых шага сбора данных (поисковые запросы — Шаг 3, площадки РСЯ — Шаг 4, сегменты ставок — Шаг 5) вынесены в изолированные субагенты (`context: fork`): они собирают гигантские TSV-отчёты в своём контексте и возвращают наверх **только сводку ≤20 строк**. Это не даёт контексту оркестратора распухнуть к моменту сборки отчёта. **Если форк недоступен** — шаги выполняются инлайн по тем же reference/scripts. Делегирование — оптимизация, а не жёсткая зависимость.

Пакет Claude Desktop должен содержать **ровно один `SKILL.md`**, поэтому субагенты — не отдельные скиллы, а **брифы** `subagents/<имя>.md`: оркестратор читает бриф и передаёт его форку как задачу вместе с аргументами. Бриф самодостаточен, методологию пересказывать не нужно.

Списком тулов форки не ограничены — имя коннектора у каждого своё, и жёсткий `allowed-tools` оставил бы субагента вообще без Директа; **read-only держится инструкцией** в блоке «Read-only — жёстко» каждого брифа.

**Шаг 4 — это перенесённый внутрь аудита движок бывшего отдельного скилла `yandex-direct-rsya-minus`**: анализатор `analyze_placements.py` + словарь `placement_patterns.json` + ruleset `rsya-minus-rules.md`. Он отдаёт готовый к вставке `minus_list.txt` по кампаниям.

**Шаг 3 — это движок бывшего скилла `yandex-direct-phrase-minus`** (`search-query-miner`): `query_analyzer.py` + `run_analysis.py` + словарь `query_patterns.json` + ruleset `phrase-minus-rules.md`. За один прогон даёт минусацию запросов (минус-слова кампании + минус-фразы группы → `minus_keywords.txt`) и действия по ключевым фразам (ставки/статус → `03_phrase_actions.md`).

## Имена артефактов

Рабочая папка: `direct-audits/<slug>/`. `00_scope.md` · `_state.json` · `01_account_map.{md,json}` · `02_campaign_performance.{md,json}` · `03_negative_candidates.json` + `minus_keywords.txt` + `03_phrase_actions.md` · `04_placement_candidates.{md,json}` + `minus_list.txt` · `05_bid_modifier_opportunities.{md,json}` · `06_creative_findings.{md,json}` · `findings.json` → `АУДИТ_<slug>.html`.

## Принципы

- **Режим решает всё.** В аудите — строго read-only (ни оркестратор, ни субагенты не пишут в аккаунт). В ведении — правки применяются, но только после гейта, с журналом и откатом, в пределах guardrails из `strategy.md`. Решение всегда за маркетологом; кампанию из паузы/черновика скилл сам не активирует ни в каком режиме.
- **Деньги: отчёты — в рублях с НДС, настройки — в микро.** НДС включён по умолчанию (`include_vat`), чтобы расход по площадкам и сегментам сходился с расходом по кампаниям. Отчёты коннектор отдаёт в рублях — их не делим. Настройки кампаний и ставки (`campaigns_get`, `keywordbids_get`: лимиты, CPA, ставки, ценность целей) — в микро, делим на 1 000 000; при записи — наоборот.
- **Кабинет и кампании — только явным выбором.** Кабинет подтверждается всегда, даже если у токена он один; кампании выбирает маркетолог. Без ответа скилл останавливается.
- **История каналов — вход, а не догадка.** Обычный путь клиента: стратегия → запуск → этот скилл. Историю каналов (`channel_history.md` / `.json` — что реклама давала до нас) скилл ищет у стратега и менеджера, в ведении кладёт в блок `history` файла `strategy.md` и не наращивает без «ОК» типы кампаний, которые уже не работали. Нет истории — собирает её из кабинета по запросу («выгрузи историю каналов») или работает с пометкой «без истории». Это не `baseline.json`: baseline — метрики в день старта ведения, история — опыт клиента до нас (`references/channel-history.md`).
- **Оплата за конверсии — свои правила.** Клики бесплатны, поэтому пороги «расход без конверсий» не применяются; вместо них — цель оплаты, мусорные конверсии и цена конверсии против KPI (`references/audit-thresholds.md`).
- **Доказательство обязательно.** Каждый флаг = числа + период + объём + порог. Мало данных — «недостаточно данных», а не выдуманный вывод.
- **Поведение — из полей самого отчёта.** `BounceRate` и `AvgPageviews` приходят вместе с расходом, если к кампании привязан счётчик. Нет связки — честная пометка «без поведения», а не догадки.

## Зависимости (для scripts)

Только стандартная библиотека Python 3 — ни pip-пакетов, ни браузера, ни сети. Это осознанное
ограничение: скрипты исполняются в песочнице Claude Desktop, где ничего этого нет.

## Коннекторы

Скиллу нужен коннектор **Яндекс Директа**; коннектор **Яндекс Метрики** — по желанию (цели, время
на сайте, посадочные, потеря кликов). Серверы работают на стороне click.ru: в Claude добавляется
только адрес.

1. **Токен click.ru.** Профиль [click.ru/userinfo.html](https://click.ru/userinfo.html) → поле
   **API Token** → скопировать или **Создать**. Токен выпускайте в том аккаунте click.ru, где
   подключены кабинеты Директа. «Пересоздать» — только при утечке: старые подключения перестанут
   работать.
2. **Адрес Директа** ([подробнее](https://help.click.ru/7738)):

   ```
   https://direct-mcp.aihub.click.ru/c/<токен click.ru>
   ```

   - `…/c/<токен click.ru>/<кабинет>` — закрепить один кабинет: логин Директа, название или ID
     в click.ru (`@` → `%40`, пробел → `%20`).
   - `…/y/<OAuth-токен Яндекса>` — кабинет, созданный напрямую в Яндексе, без click.ru.

   Старая форма `/c/<логин>/<токен>/<ID пользователя>` ещё принимается сервером, но для новых
   подключений не используется.
3. **Адрес Метрики** (по желанию):

   ```
   https://metrika-mcp.aihub.click.ru/c/<токен click.ru>
   ```

   `…/c/<токен click.ru>/<аккаунт>` — один аккаунт; `…/y/<OAuth-токен Яндекса>` — напрямую
   в Яндекс. Для форм с `/c/` в click.ru должна быть подключена интеграция Метрики.
4. **Добавить в Claude.**
   - Claude Desktop / claude.ai: **Settings → Connectors → Add custom connector** → любое имя →
     адрес → **Continue** → **Add**, затем перезапустить Claude Desktop.
   - Claude Code: `claude mcp add --scope user --transport http yandex-direct "<адрес коннектора>"`.
5. **Проверка:** в сессии появились тулы `yandex_direct_*`; попросите «покажи мои кабинеты».

⚠️ **Адрес коннектора равносилен паролю:** токен в нём открывает Директ, Вордстат, Метрику и VK
Рекламу этого аккаунта click.ru. Не пересылайте его; при утечке пересоздайте токен в профиле
click.ru.

## Установка скилла

**Claude Desktop и Claude Code — плагином, с обновлениями.** Пошаговая инструкция (Git, каталог,
автообновление) — в [README каталога ai-hub-open](https://github.com/ai-hub-open/claude-plugins#установка-в-claude-desktop).
Коротко: **Settings → Plugins → + → Add marketplace → Add from repository** →
`https://github.com/ai-hub-open/claude-plugins` → установить `yandex-direct-audit` → включить
автообновление каталога. В Claude Code то же командами:

```
/plugin marketplace add ai-hub-open/claude-plugins
/plugin install yandex-direct-audit@ai-hub-open
```

Скилл работает в режимах Cowork и Code: скажите «сделай аудит Директа» — он подключится сам, или
вызовите `/yandex-direct-audit:yandex-direct-audit`.

**Архивом (claude.ai, любой тариф).** На [странице релизов](https://github.com/ai-hub-open/yandex-direct-audit/releases)
в блоке **Assets** верхнего релиза скачайте `yandex-direct-audit.zip` (не «Source code») или
соберите сами: `python scripts/make_bundle.py`. Загрузите в **Customize → Skills → + → Upload a
skill**. Бандл не включает `.env`, `docs/`, `parked/` и рабочие папки аудитов.

Рабочие папки `direct-audits/` и `lead/` создаются в текущей папке, а не внутри плагина: папка
плагина при обновлении заменяется целиком. Если раньше скилл лежал папкой в `~/.claude/skills/`,
удалите её, иначе скилл будет загружаться дважды.
