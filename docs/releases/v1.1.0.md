# v1.1.0 — скилл знает историю рекламы клиента

Обновление с v1.0.1.

Коротко: обычно сначала делают стратегию, потом запускают кампании и только потом подключают
аудит. Теперь аудит знает, что на стратегии уже собрана **история каналов** — что прошлая
реклама клиента реально дала, — находит её и использует. Если истории нет, может собрать её
из кабинета сам. Плюс журнал правок теперь спокойно работает в Windows.

## Что изменилось для вас

**1. Аудит находит историю каналов сам.**
История каналов — файл `channel_history.md` со сводкой «канал → период → расход → заявки → цена
заявки → вывод». Его готовит стратег (`marketing-strategist`), передаёт дальше скилл запуска
(`yandex-direct-manager`). Аудит ищет этот файл в папках стратегии и запуска; если вы работали
в разных чатах Claude Desktop — просто приложите файл.

**2. История учитывается в выводах.**
Если тип кампаний (например, РСЯ) по истории уже не давал заявок, в находке аудита будет об
этом строка с цифрами — чтобы не наступить на те же грабли.

**3. Ведение опирается на стратегию и историю.**
При первом запуске ведения скилл собирает цели проекта и из папки стратегии, а историю каналов
переносит в файл стратегии ведения. Наращивать бюджет и ставки в типах кампаний, которые раньше
не работали, скилл сам не будет — только предложит, с цифрами из истории, и подождёт вашего
решения. Если целевая цена заявки сильно ниже той, что была на практике, скажет об этом сразу.

**4. История — это не «точка старта».**
У ведения есть снимок метрик в день старта — с ним скилл сравнивает, стало ли лучше. История
каналов — другое: опыт клиента до нас, по всем каналам, с выводами «работает / дорого / не дал
заявок». Скилл держит их раздельно.

**5. Нет истории — соберу.**
Скажите «выгрузи историю каналов»: скилл спросит период и что считать заявкой, соберёт историю
Директа по типам кампаний из кабинета, другие каналы — из Метрики (если ссылки размечены UTM)
или с ваших слов, и отдаст файл. Его можно приложить к стратегии или к запуску. Не хотите —
скилл работает дальше с пометкой «без истории».

**6. Журнал правок работает в Windows.**
Журнал, по которому скилл откатывает изменения в кабинете, в Windows-консоли падал на русских
буквах и значках ✅/⚠️ — правка записывалась, а скилл видел ошибку и мог записать её второй раз.
Теперь всё выводится читаемо. В Claude Desktop ошибки не было (там Linux-песочница).

## Обновление

Скачайте новую версию скилла и замените старую (в Claude Desktop — загрузите заново в
«Настройки → Возможности → Скиллы»). Подключения MCP менять не нужно. Технический список
изменений — [`CHANGELOG.md`](../../CHANGELOG.md).
