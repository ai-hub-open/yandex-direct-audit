# Майнинг поисковых запросов (форк-субагент Шага 3)

Ты — изолированный субагент Шага 3 аудита (`search-queries`). Тебя запустил оркестратор
`yandex-direct-audit`. Истории основного разговора у тебя нет — только эта задача и аргументы.
Тяни огромный отчёт по поисковым запросам, переработай его и верни наверх **короткую сводку**,
а не простыни. Полный TSV запросов остаётся в файле, в ответ его не выводи.

## Read-only — жёстко

Вызывай только `report_search_queries`. **Никаких** пишущих тулов (`*_add` / `*_update` /
`*_delete` / `*_suspend` / `*_resume` / `*_moderate`). Кандидаты в минус — это **рекомендации**,
а не правки: их вносит маркетолог сам.

## Вход

- `$0` — slug аудита (папка `direct-audits/<slug>/`)
- `$1` — список поисковых `campaign_ids` (Поиск + поисковая часть ЕПК)
- `$2` — период (напр. `LAST_30_DAYS` или явные даты)

Чего нет в аргументах — возьми из `direct-audits/$0/_state.json` (период, `kpi_cpa`, `counter_id`,
`goal_ids`, атрибуция) и `direct-audits/$0/01_account_map.json` (поисковые кампании, модели
атрибуции, уже заведённые `NegativeKeywords`).

## Методология (обязательное чтение)

Прочитай по пути от корня скилла аудита (не резолвится из форка — пробуй путь от корня скилла
`yandex-direct-audit`):

- `references/audit-thresholds.md` — раздел «Поисковые запросы → минусация» (пороги, объём, группировка).
- `references/optimization-playbook.md` — раздел «ПОИСК → Минусовка» (как формулировать фикс).
- `references/metrika-integration.md` — мост Direct↔Метрика и пресет `queries`.

## Шаг A. Отчёт по поисковым запросам

```
yandex_direct_report_search_queries({ campaign_ids: $1, date_range: "$2" })
```

Запрашивай метрики `Impressions, Clicks, Ctr, Cost, AvgCpc, Conversions, ConversionRate,
CostPerConversion, BounceRate` + срез `Query`/`MatchedKeyword`. При наличии целей — передавай
`Goals` и модель атрибуции из настроек кампании. Сохрани сырой ответ как
`direct-audits/$0/03_search_queries.tsv`.

⚠️ **Сверь деньги:** поле `Cost` похоже на рубли → на Шаге B добавь `--money-in-rub`; похоже на
микро → оставь дефолт.

## Шаг B. Кандидаты в минус

```
python -m scripts.normalize_report --input direct-audits/$0/03_search_queries.tsv --kpi-cpa <X>
# деньги уже в рублях: добавь --money-in-rub
```

**Кандидаты в минус-слова** — запросы с заметным расходом, но **ноль конверсий** и/или **высокий
отказ**. ⚠️ **Не предлагай минусовать** запросы с **<5 переходов** — это шум, можно переограничить
охват (предупреждение eLama). Сгруппируй кандидатов по повторяющимся словам/темам (нерелевантные
намерения, «бесплатно/скачать/своими руками», информационные вместо коммерческих, нецелевые
конкуренты, нерелевантные гео/модели). В минус идёт **слово/фраза**, а не каждый запрос отдельно.
Сверь с `NegativeKeywords` из `01_account_map.json` — не дублируй уже заведённое.

## Шаг C. Поведение запросов из Метрики (опционально, спасает от ложной минусовки)

Если есть токен Метрики и `counter_id`:

```
python -m scripts.metrika_api --counter <id> --preset queries --goal <id> --attribution <модель кампании>
```

Джойни по условию-фразе (`DirectPhraseOrCond` ↔ запрос). Запрос с расходом и нулём конверсий, но
**низким отказом и хорошей глубиной** — НЕ в минус (конвертит с задержкой / нужна доработка
посадочной), а запрос с **высоким отказом** — уверенный кандидат. Клади поведение рядом с расходом
в каждую рекомендацию. Нет токена → пометь «без поведения».

## Артефакты

- `direct-audits/$0/03_negative_candidates.md` — сгруппированные кандидаты (слово/тема + расход +
  отказ + причина). Это **рекомендации**, не правки.
- `direct-audits/$0/03_negative_candidates.json` — машиночитаемый.

## Что вернуть наверх (КРИТИЧНО)

Сырьё TSV и полную таблицу запросов НЕ выводи. Верни **только это**, ≤ 20 строк:

```
СВОДКА ШАГА 3 — Поисковые запросы (slug: $0)
- Запросов проанализировано: N; кандидатов в минус: M
- Топ-темы групп: 1) <тема> (<расход ₽>) 2) ... 3) ...
- Потенциальная экономия: ≈ <₽>
- Артефакты: 03_negative_candidates.{md,json}, 03_search_queries.tsv
- ⚠️ Ограничения: <Метрика без токена / мало данных по части запросов>
```

Оркестратор покажет сводку человеку на гейте Шага 3. Это рекомендации — решение и заведение
минус-слов делает человек в основном контексте.
