# Бриф субагента `rsya-placements` — Шаг 4 аудита

> **Это не отдельный скилл, а инструкция для форка.** Оркестратор `yandex-direct-audit`
> запускает изолированного субагента и передаёт ему содержимое этого файла как задачу
> плюс аргументы. Сам по себе файл не запускается.
>
> **Аргументы:** `[slug] [сетевые campaign_ids] [период] [tCPA]` — далее по тексту `$0`, `$1`, `$2`, `$3`.
>
> **Назначение:** Чистка площадок РСЯ Яндекс.Директа. Запускается оркестратором yandex-direct-audit как изолированный субагент на Шаге 4. Собирает CUSTOM_REPORT по площадкам РСЯ, прогоняет анализатор минусации и возвращает в основной контекст только компактную сводку + пути к артефактам (включая готовый minus_list.txt). Сырьё (полный TSV площадок) остаётся в форке. Read-only. Вход — slug аудита, список сетевых кампаний, период, целевой CPA, цели, атрибуция.

Ты — изолированный субагент Шага 4 аудита (`rsya-placements`). Тебя запустил оркестратор
`yandex-direct-audit`. Истории основного разговора у тебя нет — только эта задача и аргументы.
Собери сырьё по площадкам РСЯ, переработай его анализатором и верни наверх **короткую сводку**,
а не простыни. Полный TSV площадок остаётся в файле, в ответ его не выводи. Решение «отключить
площадку» и заливку в «Запрещённые площадки» делает человек в основном контексте — не ты.

## Read-only — жёстко

Вызывай **только** `yandex_direct_campaigns_get` (пробник/контекст) и `yandex_direct_report_custom`
(плюс Bash/Read/Write для файлов). Список разрешённых тулов тебе не выдан — коннектор называется у
каждого по-своему, поэтому технически пишущие тулы Директа тебе видны. **Не трогай их ни при каких
обстоятельствах:** `*_add`, `*_update`, `*_delete`, `*_suspend`, `*_resume`, `*_moderate`, `*_set`.

Рука потянулась «просто отключить площадку» — стоп: это строка в `minus_list.txt`, которую
маркетолог заливает сам.

## Вход

- `$0` — slug аудита (папка `direct-audits/<slug>/`)
- `$1` — список сетевых `campaign_ids` (кампании с РСЯ-размещением + сетевая часть ЕПК)
- `$2` — период (напр. `LAST_30_DAYS` или явные даты)
- `$3` — целевой CPA (tCPA) глобально

Чего нет в аргументах — возьми из `direct-audits/$0/_state.json` (период, `goal_ids`, атрибуция,
`tcpa`/`tcpa_map`, `counter_id`) и `direct-audits/$0/01_account_map.json` (сетевые кампании,
**модель атрибуции по каждой кампании**). Если tCPA глобально не задан, но в `01_account_map.json`
есть данные по кампаниям — собери `cpa_by_campaign.json` и передай анализатору через `--tcpa-map`.

## Методология (обязательное чтение)

Прочитай по пути от корня скилла аудита. Если относительный путь из форка не резолвится — пробуй
путь от корня скилла `yandex-direct-audit`:

- `references/rsya-minus-rules.md` целиком — пороги, гейт объёма, сигналы 1–3, словарь имён, категории.
- `references/custom-report-recipes.md` — Рецепт 1 (площадки): поля и фильтры.
- `references/mcp-tools-map.md`, раздел «Правила объёма отчётов» — чанкинг, `page_limit`, фильтры,
  офлайн-очередь. Обязателен, а не рекомендателен.
- `references/attribution.md` — модели атрибуции и что делать без целей.

## Шаг A. Отчёт по площадкам РСЯ

Сначала живой пробник: `campaigns_get({ limit: 1 })`. Пусто/ошибка → зафиксируй проблему доступа.

Собери отчёт по Рецепту 1:

```
yandex_direct_report_custom({
  report_type: "CUSTOM_REPORT",
  campaign_ids: $1, date_range: "$2",
  fields: ["CampaignName","CampaignId","AdNetworkType","Placement",
           "Impressions","Clicks","Ctr","Cost","AvgCpc",
           "Conversions","ConversionRate","CostPerConversion","Revenue",
           "BounceRate","AvgPageviews"],
  filters: [{ field: "AdNetworkType", operator: "EQUALS",       values: ["AD_NETWORK"] },
            { field: "Clicks",        operator: "GREATER_THAN", values: ["0"] }],
  page_limit: 3000,
  goals: [<goal_id>], attribution_models: ["<модель кампании>"],
  wait_seconds: 55
})
```

⚠️ **`Device` и `LocationOfPresenceName` в поля НЕ добавляй** — каждый дробит площадку на десятки
подстрок и раздувает отчёт в разы. Разбивку собирай вторым узким проходом только по топ-20
кандидатам, и только если она нужна для вывода.

**Чанкинг:** кампаний в `$1` больше пяти → по одной кампании за вызов.

**Мост в песочницу.** Ответ приходит в твой контекст, а `analyze_placements.py` читает файл —
общей файловой системы нет. Запиши **одним блоком**:

```
cat > direct-audits/$0/04_placements.tsv <<'EOF'
<весь TSV как есть>
EOF
```

При чанкинге дописывай (`>>`) без повторного заголовка. Если конверсии разбились по целям
(`Conversions_<goal>_<model>`) — сверни их в один столбец `Conversions` (сумма по целям в рамках
ОДНОЙ модели) перед прогоном.

Деньги приходят в рублях — флаг денег на Шаге B не нужен.

## Шаг B. Анализ площадок

Прогони ядро минусации:

```
python scripts/analyze_placements.py \
  --input direct-audits/$0/04_placements.tsv \
  --outdir direct-audits/$0 \
  --tcpa <tCPA>
# вместо --tcpa: --tcpa-map cpa_by_campaign.json
```

Скрипт сворачивает срез до уровня (кампания, площадка), считает CTR/CR/CPC/CPA, сравнивает с
целевым и средним CPA, применяет пороги и гейт объёма, классифицирует мусорные имена по
`assets/placement_patterns.json` и пишет `candidates.json` + `minus_list.txt` + `report.md` в
`direct-audits/$0/`. Под нишу крути флаги (`--min-clicks`, `--ctr-warn`, `--ctr-fraud`, `--bounce`,
`--cpa-cand`, `--cpa-strong`) — раздел «Тюнинг под нишу» в `rsya-minus-rules.md`.

**Переименуй под схему артефактов аудита** (чтобы Шаг 7 получил ожидаемые имена входов):
- `direct-audits/$0/candidates.json` → `direct-audits/$0/04_placement_candidates.json`
- `direct-audits/$0/report.md` → `direct-audits/$0/04_placement_candidates.md`
- `direct-audits/$0/minus_list.txt` — **оставь под этим именем** (готовый список для вставки).

## Шаг C. Поведение как доказательство

`BounceRate` и `AvgPageviews` пришли прямо в отчёте Шага A (Директ берёт их из привязанного
счётчика), и `analyze_placements.py` уже учитывает отказы флагом `--bounce`. Твоя работа — вынести
это в формулировку находки, чтобы решение было очевидным:

«Площадка X — расход 12 400 ₽, 0 конверсий, отказы 81%, глубина 1,1 страницы → отключить,
уверенность высокая».

Колонки пустые (счётчик к кампании не привязан) → пометь «без поведения» и строй вывод по расходу
и конверсиям. Ядро минусации работает и без этого — просто с меньшей уверенностью.

## Что вернуть наверх (КРИТИЧНО)

Сырьё TSV и полную таблицу площадок НЕ выводи — они в файлах. Верни **только это**, ≤ 20 строк:

```
СВОДКА ШАГА 4 — Площадки РСЯ (slug: $0)
- Площадок: N. 🔴 X · 🟠 Y · 🟡 Z · ✅ W · ⚪ V
- Потенциальная экономия (🔴+🟠 без конверсий): ≈ <₽>
- Топ-кандидаты: 1) <площадка> — <расход ₽>, <причина> 2) ... 3) ...
- Артефакты: 04_placement_candidates.{md,json}, minus_list.txt, 04_placements.tsv
- ⚠️ Ограничения: <отчёт не собрался за 2 попытки / без поведения (счётчик не привязан) / мало данных>
```

Оркестратор покажет сводку человеку на гейте Шага 4. Главный actionable-артефакт —
**`minus_list.txt`**: готовый список по кампаниям, который маркетолог копирует в «Запрещённые
площадки и внешние сети» по каждой кампании отдельно (🔴 — заливать, 🟠 — на его решение).
Скилл сам ничего не отключает.
