# Бриф субагента `search-queries` — Шаг 3 аудита

> **Это не отдельный скилл, а инструкция для форка.** Оркестратор `yandex-direct-audit`
> запускает изолированного субагента и передаёт ему содержимое этого файла как задачу
> плюс аргументы. Сам по себе файл не запускается.
>
> **Аргументы:** `[slug] [поисковые campaign_ids] [период] [tCPA]` — далее по тексту `$0`, `$1`, `$2`, `$3`.
>
> **Назначение:** Майнинг поисковых запросов Яндекс.Директа — минусация и действия по ключевым фразам. Запускается оркестратором yandex-direct-audit как изолированный субагент на Шаге 3. Тянет огромный отчёт по поисковым запросам и прогоняет движок phrase-minus: даёт минус-слова уровня кампании (по словарю паттернов), минус-фразы уровня группы (≥25 кликов без конверсий), список «проверь вручную» и действия по ключевым фразам (отключить/понизить/поднять ставку по CPA). Возвращает наверх только сводку + пути к артефактам (включая готовый minus_keywords.txt). Сырьё (полный TSV запросов) остаётся в форке. Read-only. Вход — slug аудита, поисковые кампании, период, целевой CPA.

Ты — изолированный субагент Шага 3 аудита (`search-queries`). Тебя запустил оркестратор
`yandex-direct-audit`. Истории основного разговора у тебя нет — только эта задача и аргументы.
Тяни огромный отчёт по поисковым запросам, прогони движок минусации и верни наверх **короткую
сводку**, а не простыни. Полный TSV запросов остаётся в файле, в ответ его не выводи.

За один прогон ты даёшь **два** результата: (A) **действия по ключевым фразам** (ставки/статус) и
(B) **минусацию запросов** (минус-слова кампании + минус-фразы группы + «проверь вручную»).

## Read-only — жёстко

Вызывай **только** `yandex_direct_report_search_queries` (плюс Bash/Read/Write для файлов). Список
разрешённых тулов тебе не выдан — коннектор называется у каждого по-своему, поэтому технически
пишущие тулы Директа тебе видны. **Не трогай их ни при каких обстоятельствах:** `*_add`, `*_update`,
`*_delete`, `*_suspend`, `*_resume`, `*_moderate`, `*_set`.

Кандидаты в минус и действия по фразам — это **рекомендации**: вносит маркетолог сам. Рука
потянулась «просто добавить минус-слово» — стоп, это строка в `minus_keywords.txt`.

## Вход

- `$0` — slug аудита (папка `direct-audits/<slug>/`)
- `$1` — список поисковых `campaign_ids` (Поиск + поисковая часть ЕПК)
- `$2` — период (напр. `LAST_30_DAYS` или явные даты)
- `$3` — целевой CPA (tCPA) — нужен для действий по фразам

Чего нет в аргументах — возьми из `direct-audits/$0/_state.json` (период, `kpi_cpa`/`tcpa`,
`counter_id`, `goal_ids`, целевые регионы, бренды конкурентов) и
`direct-audits/$0/01_account_map.json` (поисковые кампании, модели атрибуции, уже заведённые
`NegativeKeywords`).

## Методология (обязательное чтение)

Прочитай по пути от корня скилла аудита (не резолвится из форка — пробуй путь от корня скилла
`yandex-direct-audit`):

- `references/phrase-minus-rules.md` целиком — пороги действий по фразам, минусация запросов,
  режим без конверсий, маппинг полей, куда вносить.
- `references/attribution.md` — коды моделей, правило выбора по кампании, что делать без целей.
- `references/mcp-tools-map.md`, раздел «Правила объёма отчётов» — чанкинг, `page_limit`, фильтры,
  офлайн-очередь.

## Шаг A. Отчёт по поисковым запросам

**Прочти раздел «Правила объёма отчётов» в `references/mcp-tools-map.md`** — он обязателен, а не
рекомендателен. Отчёт по запросам — самый крупный в аудите, и он идёт через контекст.

```
yandex_direct_report_search_queries({
  campaign_ids: $1, date_range: "$2",
  fields: ["CampaignName","CampaignId","AdGroupName","Criteria","Query",
           "Impressions","Clicks","Cost","Conversions"],
  filters: [{ field: "Clicks", operator: "GREATER_THAN", values: ["0"] }],
  page_limit: 5000,
  goals: [<goal_id>], attribution_models: ["<модель кампании>"],
  wait_seconds: 55
})
```

**Чанкинг:** кампаний в `$1` больше пяти → тяни по одной кампании за вызов и склеивай TSV.
Пять и меньше — одним отчётом.

**Мост в песочницу.** MCP отвечает в твой контекст, а `run_analysis.py` читает файл — общей
файловой системы между ними нет. Поэтому запиши ответ в файл **одним блоком**, не порциями:

```
cat > direct-audits/$0/03_search_queries.tsv <<'EOF'
<весь TSV как есть>
EOF
```

При чанкинге дописывай в тот же файл (`>>`), заголовок TSV повторно не вставляй.

⚠️ **Проверь конверсии:** нет колонки `Conversions` или она везде пустая при ненулевых кликах
(счётчик/цели не привязаны) — запускай с `--no-conversions` и **подними «алярму»** маркетологу:
без целей оптимизация по ставкам слепая, отправь настроить цели (это находка high).

Деньги приходят в рублях — флаг денег на Шаге B не нужен.

## Шаг B. Минусация и действия по фразам

```
python scripts/run_analysis.py \
  --input direct-audits/$0/03_search_queries.tsv \
  --outdir direct-audits/$0 \
  --tcpa <tCPA> \
  [--target-geo "москва,московская"] [--competitors "бренд1,бренд2"] [--no-conversions]
```

Скрипт пишет в `direct-audits/$0/`: `queries_candidates.json` (полная выкладка), `minus_keywords.txt`
(два уровня, готов к вставке), `phrase_actions.md` (таблица действий по фразам). Пороги под нишу
крути флагами (`--phrase-min-clicks`, `--query-min-clicks`, `--cpa-high`) — см. «Тюнинг» в
`phrase-minus-rules.md`.

**Переименуй под схему артефактов аудита:**
- `direct-audits/$0/queries_candidates.json` → `direct-audits/$0/03_negative_candidates.json`
- `direct-audits/$0/phrase_actions.md` → `direct-audits/$0/03_phrase_actions.md`
- `direct-audits/$0/minus_keywords.txt` — **оставь под этим именем** (готовый список для вставки).

## Шаг C. Защита от ложной минусовки (если пришло поведение)

Попробуй добавить в `fields` Шага A `BounceRate` и `AvgPageviews`. Поле доступно не для всех типов
отчётов — вернулась ошибка по полю, убери его и повтори **один раз**, дальше работай без поведения.

Пришло — используй как предохранитель: запрос, который ядро предложило в минус-фразу группы
(≥25 кликов, 0 конверсий), но с **низким отказом и хорошей глубиной** — НЕ режь (конвертит с
задержкой либо надо дорабатывать посадочную); высокий отказ — уверенный кандидат. Помечай такие
в `03_phrase_actions.md`. Поле пустое или недоступно → «без поведения», решение по расходу и
конверсиям.

## Что вернуть наверх (КРИТИЧНО)

Сырьё TSV и полные таблицы НЕ выводи. Верни **только это**, ≤ 20 строк:

```
СВОДКА ШАГА 3 — Поисковые запросы (slug: $0)
- Действия по фразам: 🔴 stop X · 🟠 lower Y · 🟢 raise Z · ⚪ hold W
- Минус-слова (кампания): N · минус-фразы (группа): M · проверь вручную: K
- Потенциальная экономия: ≈ <₽>
- Артефакты: 03_negative_candidates.json, minus_keywords.txt, 03_phrase_actions.md, 03_search_queries.tsv
- ⚠️ Ограничения: <без конверсий (счётчик/цели не привязаны) / без поведения / отчёт не собрался за 2 попытки / мало данных>
```

Оркестратор покажет сводку человеку на гейте Шага 3. Главный actionable — **`minus_keywords.txt`**
(минус-слова кампании + минус-фразы группы, заливает маркетолог сам) и **`03_phrase_actions.md`**
(что сделать со ставками фраз). Это рекомендации — решение за человеком.
